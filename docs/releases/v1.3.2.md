## 本版改动

**Android（阶段 C）**
- 一句话带命令：`WakeMatcher.matchWithRest()` 取唤醒词后半句，「小鲸小鲸，帮我查天气」一句话说完直接执行，不再先播「我在」再听一遍；只有语气词（「嗯」「帮我」）仍走两段式。
- 音频焦点 / 来电：主动聆听时申请短时音频焦点，待机唤醒不占焦点；`AudioManager.mode` 轮询识别来电；被抢占时暂停并提示，恢复后自动回到待唤醒。
- 修复打断恢复死循环：打断期间只停识别器，**保留焦点请求与来电轮询**；此前协调器再补一次 `stopListening()` 会把恢复监听清掉，来电结束后永远等不到恢复事件。
- 退后台用 `suspend()` 而不是 `disable()`：停采集但保留语音开关，回前台按原设置恢复，不再冒一句「语音关掉啦」。

**Windows（阶段 E）**
- 托盘图标（显示/隐藏、语音开关、设置、退出）与开机自启，设置面板新增对应开关；托盘动作与右键菜单共用同一套行为。
- 一句话带命令：待机从「唤醒词小语法」切到整段听写，由 core 的路由剥唤醒词并取后半句；关掉开关则退回低功耗两段式。
- 多显示器变化后重新约束窗口；音频中断/恢复状态机补齐。

**macOS（阶段 D/E）**
- 本地语音闭环：`SFSpeechRecognizer` 本机识别 + `AVSpeechSynthesizer` 播报。
- 真 KWS：sherpa-onnx 常驻子进程做本地关键词唤醒，系统识别只负责指令段；子进程挂了退回「系统识别 + 文本匹配」。关键词阈值目前按 TTS 音频标定，真机需重新标定。

**core / 测试**
- 新增 `VoiceInterruptionEvent` / `VoiceEngineRecoveredEvent`、`VoiceEngineConfig.oneShotCommand`、`spoken_command.dart` 的语气词判定；`VoiceEventRouter` 待机只认 final，避免整段 ASR 把后半句截断。
- 补了 Android 引擎、唤醒词、一句话命令、中断恢复等回归用例。

## 已知限制

- Android 的唤醒仍是「系统识别 + 文本匹配」的过渡方案，耗电与延迟不如真 KWS；真正的本地 KWS 目前只在 macOS 落地。
- 桥接服务器是明文 HTTP + Bearer，仅供局域网 / ZeroTier 使用，不要暴露公网。
- Android / Windows 安装包用 debug / 自签方式，未做正式发行签名与公证。
